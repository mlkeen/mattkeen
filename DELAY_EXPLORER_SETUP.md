# Delay Explorer — Installation

## Safe installation into an existing project

1. Back up `C:\Users\Matt\Documents\mattkeen`.
2. Unzip the **site-update** package into that directory (merge folders, replace matching files). Your existing `data/raw/`, `data/processed/`, and other imported workbooks are not included in this update.
3. From the project's PowerShell terminal:

   ```powershell
   .\.venv\Scripts\python.exe scripts\publish_delays.py
   ```

4. Restart Flask:

   ```powershell
   .\.venv\Scripts\python.exe run.py
   ```

5. Open `http://127.0.0.1:5000/projects/intercity-rail/delays`.

The publisher reads `data/processed/delay_by_code.csv` generated by the existing FRA ETL. It validates required identity/provenance fields, fiscal quarter, and nonnegative finite delay minutes before publishing to `app/data/fra_delays.json` via an atomic replacement. A blank delay-minute cell is excluded and counted; a zero is a recorded zero. If the publisher finds any negative delay minutes, it stops for investigation rather than silently dropping them.

## Analytical guardrails

- Delay-by-code records include host train-miles repeated for many delay codes. **Only delay minutes are summed.**
- Values show aggregate *train delay minutes*, not customer OTP, a passenger-weighted delay measure, or delay minutes per 10,000 train-miles. Service volumes can drive raw totals.
- Cause codes remain exactly as reported: no guessed descriptions.
- 'Host railroad' tells you where the delay is attributed geographically/operationally; the separate responsibility field tells you who is responsible.
- Distinct subservices remain separate and unnamed service groupings are never auto-joined to financial-ridership routes.
- FY2021 Q4 through FY2026 Q3 are expected if all quarters are present, but only local publisher output controls display.

## Validation

Run `.\.venv\Scripts\python.exe -m pytest -q tests/test_delay_explorer.py`.

If the site reports unpublished delay data, check that `app/data/fra_delays.json` exists, then restart Flask. The JSON is not shipped in the site-update package since your full processed CSV has not been uploaded.
